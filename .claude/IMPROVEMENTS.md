# Improvements

- 2026-08-16 backend/alembic/env.py: CHECK constraints stay outside `alembic check` — Alembic's `checkconstraint_byname` plugin compares them by name only, so editing a constraint's expression while keeping its name passes. No Alembic setting closes this; it needs a comparison of `pg_constraint.consrc` against the model, or nothing. `compare_server_default` is deliberately still off and is no longer an open gap: measured 2026-08-17, all 127 remaining diffs say the same thing (database has a `DEFAULT`, model declares only a client-side `default=`) and the two sides agree on the value for every one of the 128 comparable columns. `validate_column_defaults` in `backend/scripts/validate_migrations.py` now guards the failure that uniformity could hide.
- 2026-08-17 frontend/features/matches/components/match-row.tsx: a match row is a desktop layout — `w-[420px]` and `w-40`/`w-25` blocks — so on a phone it now scrolls horizontally inside the list rather than stretching the page. Readable, but a swipe per row. The smurf-boost result card solves the same problem properly by stacking (`smurf-boost-mobile.spec.ts` asserts the table is hidden and a `<dl>` stack shows instead); match-row deserves the same treatment.
- 2026-08-17 frontend/e2e: the Playwright suite runs in neither `test.sh` nor CI, so `player-pages-mobile.spec.ts` and `smurf-boost-mobile.spec.ts` only catch a regression when someone remembers to run `npm run test:e2e`. Both are cheap (~7s with mocked APIs) and would fit the frontend gate.
- 2026-08-17 backend/app/features/players/router.py: `POST /players/add-tracked` has no caller left — the only frontend consumer was the `AddTrackedPlayer` component cluster deleted on 2026-08-17, and the live add flow goes through `POST /players/discover` + `POST /players/{puuid}/track` in `player-selector.tsx`. Its onboarding sync (`create_or_get_player_sync` at router.py:561) and the SYNC_BUSY path behind it are therefore unreachable from the app. Either delete the endpoint or point a surface at it.
- 2026-08-17 frontend/app/settings/settings-helpers.ts, frontend/features/auth/utils/login-error.ts: three hand-rolled error-carrying `Error` subtypes now coexist — `MutationError`, `PlayerTrackingError` and `AuthLoginError` — alongside the `ApiRequestError` that carries the whole normalized `ApiError`. The first two could be a `kind` check on the unwrapped `ApiError`; `AuthLoginError` reads a raw `fetch` payload and is the one with a real reason to differ.
