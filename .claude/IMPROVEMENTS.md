# Improvements

- 2026-08-16 backend/app/features/players/background_sync.py: run_background_match_sync overlaps near-totally with jobs/player_sync.run_player_sync (both sync one player's matches and record an execution), but with different concurrency gating — JobExecution bookkeeping vs PlayerSyncRun claiming. Consolidating them into one entry point with one gating story would delete a duplicated sync path; needs a semantic decision about which gate wins.
- 2026-08-16 frontend/features/matches/components/match-history.tsx: the sync-run poll (~line 758) has no error path — if the first GET /players/{puuid}/sync/{id} fails, the query settles in error, refetchInterval sees undefined status and stops, and isUpdating never resets, leaving the Update button disabled until reload. Reviewer-confirmed; fix is deriving the busy flag from run status (player-card.tsx does this) and handling syncRunQuery.error.
- 2026-08-16 frontend/features/matches/components/match-history.tsx: the sync tracking is a diverged copy of player-card.tsx:134-240 — it skips /sync/active adoption (reload mid-sync loses the poll), the two surfaces don't see each other's runs, and a second click on an attach-to-existing 200 toasts "update started" for a run it didn't start. Extract a shared usePlayerSyncRun(puuid) hook into features/players.
- 2026-08-16 frontend/components/ui/card.tsx: CardTitle renders h3, but six call sites put buttons/badges/block content inside it (job-card.tsx:637 and others) — invalid content model and screen readers announce whole cards as headings. Needs the heading scoped to the text span or an asChild escape hatch.
- 2026-08-16 frontend/components/providers.tsx: the global QueryCache error toast double-reports on surfaces that already render inline query errors (match-history, smurf-boost-detection); meta.silenceErrorToast exists but has zero call sites.
- 2026-08-16 frontend/features/matches/components/match-history.tsx: handledSyncRunIds grows unboundedly and is never cleared for a re-run of the same id; if the backend reuses a run id, the terminal-status effect silently skips it and isUpdating sticks. Same cluster as the sync-poll issues above; fix together via the shared usePlayerSyncRun hook.
- 2026-08-17 backend/app/features/jobs/router.py: POST /jobs/sync-player/{puuid} is dead (zero frontend callers, zero tests — only a comment in match-history.tsx references it) and misleading: it accepts a puuid but triggers MatchFetcherJob/PlayerUpdaterJob without target_puuids, so it syncs every tracked player, not the one named in the URL. Delete it.
- 2026-08-16 frontend/tests/dialog-contract.test.ts: the dialog-white-border rule is enforced by fragile regex source-scanning; making the class the default inside DialogContent's cn() would be zero-visual-change and unbreakable.
