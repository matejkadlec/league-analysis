# Improvements

- 2026-08-16 backend/alembic/env.py: CHECK constraints stay outside `alembic check` — Alembic's `checkconstraint_byname` plugin compares them by name only, so editing a constraint's expression while keeping its name passes. No Alembic setting closes this; it needs a comparison of `pg_constraint.consrc` against the model, or nothing. `compare_server_default` is deliberately still off and is no longer an open gap: measured 2026-08-17, all 127 remaining diffs say the same thing (database has a `DEFAULT`, model declares only a client-side `default=`) and the two sides agree on the value for every one of the 128 comparable columns. `validate_column_defaults` in `backend/scripts/validate_migrations.py` now guards the failure that uniformity could hide.
- 2026-08-17 frontend/components/ui/table.tsx, frontend/features/matches/components/match-history-controls.tsx: two surfaces still answer a phone with a horizontal scroll rather than a reflow. Every `<Table>` renders inside `div.relative w-full overflow-auto`, so the champion-stats, lane-stats and matchmaking-history tables all need a swipe at 390px; the queue-filter strip at `match-history-controls.tsx:194` is 770px inside a 308px column. Measured 2026-08-17 on the populated fixture. `player-pages-mobile.spec.ts` deliberately does not assert on these — a document-wide "nothing scrolls sideways" check also flags every `truncate` element, since truncation is exactly `scrollWidth > clientWidth`, so closing these needs a per-surface assertion like the `data-testid="match-list"` one.
- 2026-08-17 frontend/e2e: the specs mock `**/api/v1/**` but not Data Dragon, so every run reaches `ddragon.leagueoflegends.com` for champion icons. Now that the suite is in the gate, that is a public-internet dependency in CI: the requests 403 today and the tests still pass, but a slow or blocked upstream turns into a flaky gate. Blocking non-API requests in the three harnesses would close it.
- 2026-08-17 backend/app/features/players/router.py: `POST /players/add-tracked` has no caller left — the only frontend consumer was the `AddTrackedPlayer` component cluster deleted on 2026-08-17, and the live add flow goes through `POST /players/discover` + `POST /players/{puuid}/track` in `player-selector.tsx`. Re-verified 2026-08-17: no HTTP caller anywhere — the only remaining references are four direct Python calls from `backend/tests/test_players_background_maintenance.py`, which exists to test this route. It is the one endpoint that adds, tracks and starts the initial sync in a single call; the live path leaves the new player unsynced until someone presses Update, because `POST /{puuid}/track` does not start a sync. So this is a product call, not a cleanup: either delete it and accept that, or wire the track button to `POST /{puuid}/sync` and then delete it.
- 2026-08-17 frontend/app/settings/settings-helpers.ts, frontend/features/auth/utils/login-error.ts: three hand-rolled error-carrying `Error` subtypes now coexist — `MutationError`, `PlayerTrackingError` and `AuthLoginError` — alongside the `ApiRequestError` that carries the whole normalized `ApiError`. The first two could be a `kind` check on the unwrapped `ApiError`; `AuthLoginError` reads a raw `fetch` payload and is the one with a real reason to differ.
