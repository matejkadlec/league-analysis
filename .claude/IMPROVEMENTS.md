# Improvements

- 2026-08-17 frontend/components/ui/table.tsx: every `<Table>` renders inside `div.relative w-full overflow-auto`, so the champion-stats, lane-stats and matchmaking-history tables all answer a 390px phone with a swipe rather than a reflow. Measured 2026-08-17 on the populated fixture. The document itself stays honest — the scroll is inside the card — so this is a readability call, not a layout defect, and closing it means deciding per table which columns a phone drops. The queue-filter strip that used to share this entry was fixed on 2026-08-18: it wraps below `xl` and `player-pages-mobile.spec.ts` now asserts `scrollWidth - clientWidth <= 1` on `data-testid="match-history-queue-filters"` (462px of overflow before the fix, 0 after). A table fix wants the same per-surface assertion — a document-wide "nothing scrolls sideways" check is useless here, because it also flags every `truncate` element, truncation being exactly `scrollWidth > clientWidth`.
- 2026-08-17 backend/app/features/players/router.py: `POST /players/add-tracked` has no caller left — the only frontend consumer was the `AddTrackedPlayer` component cluster deleted on 2026-08-17, and the live add flow goes through `POST /players/discover` + `POST /players/{puuid}/track` in `player-selector.tsx`. Re-verified 2026-08-17: no HTTP caller anywhere — the only remaining references are four direct Python calls from `backend/tests/test_players_background_maintenance.py`, which exists to test this route. It is the one endpoint that adds, tracks and starts the initial sync in a single call; the live path leaves the new player unsynced until someone presses Update, because `POST /{puuid}/track` does not start a sync. So this is a product call, not a cleanup: either delete it and accept that, or wire the track button to `POST /{puuid}/sync` and then delete it.
